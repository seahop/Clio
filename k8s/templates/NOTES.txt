MANAGING SECRETS
{{- if .Values.secrets.existingSecret }}
  Secrets come from the externally managed Secret "{{ .Values.secrets.existingSecret }}".
  After changing it, restart the backend:
    kubectl rollout restart deployment -n {{ include "clio.namespace" . }} \
      {{ include "clio.fullname" . }}-backend
{{- else }}
  All passwords and cryptographic secrets are auto-generated on first install
  and preserved across upgrades — and across `helm uninstall` (the Secret is
  kept alongside the PVCs, so a reinstall reuses it).
  Rotation — safe for JWT_SECRET, REDIS_PASSWORD, and the bootstrap
  ADMIN/USER passwords (remove just that key, then helm upgrade):
    kubectl patch secret clio-secrets -n {{ include "clio.namespace" . }} --type=json \
      -p='[{"op":"remove","path":"/data/JWT_SECRET"}]'
  NEVER delete the whole Secret: POSTGRES_PASSWORD only applies at initdb
  (rotate with ALTER ROLE inside postgres first), and rotating
  FIELD_ENCRYPTION_KEY or REDIS_ENCRYPTION_KEY permanently destroys
  already-encrypted data.
{{- end }}

UPGRADING
  Upgrade to a specific chart version — the chart version pins the app
  version (this release: chart {{ .Chart.Version }}, app {{ .Chart.AppVersion }}):
    helm upgrade {{ .Release.Name }} oci://ghcr.io/seahop/charts/clio --version <chart-version> \
      -n {{ include "clio.namespace" . }} -f my-values.yaml
  Leave backend.image.tag / frontend.image.tag blank so the images follow the
  chart. Always pass -n {{ include "clio.namespace" . }} so release state stays in this namespace.
