MANAGING SECRETS
  All passwords and cryptographic secrets are auto-generated on first install
  and preserved across upgrades.
  Rotation — safe for JWT_SECRET, REDIS_PASSWORD, and the bootstrap
  ADMIN/USER passwords (remove just that key, then helm upgrade):
    kubectl patch secret clio-secrets -n {{ include "clio.namespace" . }} --type=json \
      -p='[{"op":"remove","path":"/data/JWT_SECRET"}]'
  NEVER delete the whole Secret: POSTGRES_PASSWORD only applies at initdb
  (rotate with ALTER ROLE inside postgres first), and rotating
  FIELD_ENCRYPTION_KEY or REDIS_ENCRYPTION_KEY permanently destroys
  already-encrypted data.
  To patch a single value without rotation:
    kubectl patch secret -n {{ include "clio.namespace" . }} clio-secrets \
      --type=merge -p '{"stringData":{"REDIS_PASSWORD":"new-value"}}'
    kubectl rollout restart deployment -n {{ include "clio.namespace" . }} \
      {{ include "clio.fullname" . }}-backend

UPGRADING
  helm upgrade clio ./k8s -n {{ include "clio.namespace" . }} -f my-values.yaml
  (always pass -n {{ include "clio.namespace" . }} so release state stays in this namespace)

  Image tag pinning (recommended for production):
    helm upgrade clio ./k8s -n {{ include "clio.namespace" . }} \
      --set backend.image.tag=1.2.3 \
      --set frontend.image.tag=1.2.3
